## 3. Hard constraints — do not re-investigate

| APRS TX over analog FM | **WORKS — proven on-air 2026-10-16** (overturns the 2026-03 "impossible" verdict). The stereo-frame experiment (`docs/deep-dive/15-…` §3.1) was run with a HackRF: feeding the OEM TX path **8 kHz stereo-duplicated** frames via an `AudioRecord.read` after-hook (riding the OEM PTT, keyed by the `com.interphone.ptt.down/up` broadcasts), a 1200 Hz tone TX'd as **1200 Hz** and 2200 Hz as **2200 Hz** (correct); the old **mono** format doubled them to 2400/3600 Hz — that was the whole bug. No out-of-band receive (220 MHz included) is possible over UART; an app showing an out-of-band frequency is wrong about the radio. |
| **Fine tuning (Doppler)** | **The radio tunes in 500 Hz steps exactly** (measured 2026-10-22, owner's Armor, VFO `0x23` writes + 1 kHz test tone at low power on 467.625 MHz, one HackRF capture, carrier = mean FM instantaneous frequency): requested 0 / +500 / +1000 / +1500 / +2500 / +5000 / 0 Hz landed at 0 / +499.8 / +1000.3 / +1498.9 / +2499.5 / +4999.6 / −1.5 Hz, so the synthesizer is not limited to a 5/6.25/12.5 kHz grid. Off-grid writes are acknowledged (`sr=0`): a real ISS pass the same day retuned 437.5570 → 437.5445 MHz in 2 kHz steps, all accepted. The common +800 Hz offset is the radio's and the HackRF's crystal errors together (not separable without a reference). SignalDeck's 500 Hz Doppler rounding is therefore real. Bench: DIAG `vfo --ei hz N` (low power unless `--ei power 1`) + `testtone --ei ms 2000`, `scratchpad/txsteps.sh` + `freqsteps.py`. |
| **Signal reading after a retune** | **The module's RSSI (0x32) needs about 0.7 s after a 0x23 retune** (measured 2026-10-22, HackRF carrier at 5 ft): it answers a query only once its next reading is ready (~0.5–0.6 s after the write), and readings taken ~0.6 s after the retune are 15–20 dB low; from 0.7 s on they match the steady reading (the squelch byte makes no difference). So any sweep is ~0.7 s per step (SignalDeck's band scope: 2 m in 25 kHz steps ≈ 2 min). |
| Hardware LED control | MCU firmware only; no app command |
| **NOAA APT satellites** | **All decommissioned in 2025** (NOAA-18 Jun 6, NOAA-19 Aug 13, NOAA-15 Aug 19; transmitters off) — nothing to receive. The APT decoder was still rebuilt and HackRF-bench-verified 2026-10-17 (see [[noaa-apt-bench-findings]]); at the real ±17 kHz deviation this radio's narrow-FM discriminator distorts the 2400 Hz subcarrier (aliased harmonics at 800/3200 Hz) — mitigated with envelope notches, not fixable in hardware. Don't invest further unless a satellite is re-activated. |
| **Transmit length** | **The stock `0x3B` handler stores the byte it is sent. There is no `min(tot, 30)`.** The timer counts 100 wakes per unit, and a unit is one second. A byte of 0 **turns the timer off**; the OEM app (`sendSetTotCmdToMdl`) and SignalDeck's boot handshake (`setTot(0)`) both send 0, so on stock firmware the module has no time-out at all (its own start-up value is 120). The 2026-10-16 keys that ended near 30 s were the apps' countdowns (OEM `PERSON_LIMIT_SEND_TIME = 30`, module `TX_LIMIT_S = 30`), not the module. FW19, measured 2026-10-24, writes 120 when the byte is 0 or above 120; two low-power streams ran 45.12 s and the module sent `SEND_STOP` itself. Op 7's `drop_ptt` leaves the module's TX state flagged, so the time-out timer kept running and sent a second `SEND_STOP` exactly 120 s after key-on (FW20 fixes it; until then the host sends `0x26` off after the module's status 4). SignalDeck is to send 120 instead of 0 (review of FW19, `radio_firmware/reviews.md`). SignalDeck's voice watchdog is still 28 s, and `txPcmOneShot` still refuses audio longer than ~28.5 s, so SSTV TX is still Robot 24 Color / Robot 12 BW / Robot 8 BW only. Also: **wait ≥ 3.5 s after a retune before keying** (`RETUNE_SETTLE_MS`) — the OEM channel-change completes ~3 s later and stops a transmission in progress. See [[radio-30s-transmit-timeout]]. |
| **TX vs. USB cable** | **The radio's own transmission can reset the phone's USB port** (measured 2026-10-19 in the owner's car, wired Android Auto): on 2 m TX **144.770 MHz high power** every key-up dropped USB about 1.5 s in (logcat `UsbPortManager: USB port changed` → `ACTION_POWER_DISCONNECTED` → `Projection … released`), and Android Auto reconnected after un-key; **146.370 MHz on the same band did not**, nor UHF 448.550/467.625. The same on the phone's and the car screen's Talk (one code path). The antenna is at the far end of the phone, so the cable itself picks up the RF and only some frequencies couple. Not fixable in software: the standalone app detects it (Android Auto disconnect or charging stopped during/≤3 s after TX → history + notification with remedies: ferrite choke, shorter shielded cable, Low power for the channel, wireless AA). Don't chase it as an app bug. |
| **POCSAG / DAPNET paging** | **RX: decodable with a calibrated decision-feedback equalizer and BCH correction inside the feedback loop** (deep dive 2026-10-22, `docs/pocsag-deep-dive-2026-10-22.md`): plain slicing gives 21–23 % bit errors (AC-coupled audio, the same cause as DCS), but a feed-forward + 250-bit decision-feedback equalizer trained once on random-bit calibration, with each codeword BCH-corrected before its bits are fed back, decoded an independent reception blind at 2.5 kHz deviation with 0 errors. Limits: at the standard 4.5 kHz the receiver's internal limiter compresses (the module volume byte acts after it) and the floor stays ≈ 1–2 % (partial pages); the equalizer is transmitter-shape specific (real transmitter recordings retransmitted through the radio failed). Not a feature yet. **TX: not feasible for real pagers** — the transmit path (pre-emphasis + low cut) gives 17 % errors at a pager-like discriminator, and the pre-distortion that fixes it needs 13–20× more drive than the audio input accepts. |
| **M17** | **RX: decodable at the standard ±2.4 kHz with a calibrated decision-feedback equalizer** (deep dive 2026-10-22, `docs/m17-deep-dive-2026-10-22.md`, tools in `tools/m17-research/`): the receive audio loses everything below ~250 Hz (−25…−37 dB), so a plain M17 demodulator decodes nothing, but a DFE (±4 symbols feed-forward, 16–48 symbols feedback, cubic terms, timing tracked per frame) trained on one HackRF transmission decoded independent transmissions 100/100 frames at 40–100 % deviation. Calibrated per phone; an adaptive equalizer is the app design. **Firmware receive route found 2026-10-24 (R-C, `radio_firmware/reviews.md` RC40):** with `WORK_MODE` `0x80`, `FM_BANDWIDTH` bits 4+6 clear and AT1846S `0x58` = `0xBCFD`, the HR-C7000's FM receive RAM (`0x160004E0`, mirror of TX RAM) holds a **flat** baseband (50 Hz–1 kHz within ±0.3 dB); each bypass alone is ~−20 dB at 100 Hz (two filters in series: AT1846S, then C7000). Getting it to the phone (UART speed switch or an MCU slicer) is the open design. **R-D (RD10, 2026-10-24): the phone's own receive audio goes flat with the single AT1846S write `0x58` = `0xBCFD` held (op 6 variant 3): 50 Hz −0.6, 100 Hz +1.2, 3.8 kHz +1.7 dB against 1 kHz, where the plain path is −27.6, −24.5 and −17.0 dB; the C7000 filters are not in the phone's path (variant 4 identical); any channel write clears it (`at1846_tune` writes `0x8405`). So the first receive design is that write held while SignalDeck's existing audio path feeds the decoders (R-E, 2026-10-24: plain decode on the held path still fails at ~19 % symbol errors, but the path is **linear** with exact ±1/±3 levels and a long linear distortion, a ~9 dB dip at 400–600 Hz plus the AC coupling's group delay; a **fixed ±20-symbol linear equaliser** fitted on one recording decodes another at 0 symbol errors, LSF CRC 13/13, Golay 0 25/25, `tools/m17-research/heldpath_eq.py`; **receive design final (R-F, 2026-10-24): bypass held + a fixed 41-tap per-phone-model equaliser applied before acquisition + the existing audio path and frame decoder**; on 18 independent HackRF transmissions (other callsigns, random payloads, ±2.4 and ±1.9 kHz) every clip locks with LSF CRC, payload-exact frames 98–100 % at −87/−93 dBm and ~95 % at −99 dBm, `tools/m17-research/heldpath_rf_score.py`; the ~9 dB dip at 500 Hz is the ES8311 (the C7000 receive RAM is flat there), so the taps are a phone-model table; the pass measure is payload-exact frames, not "Golay 0"; POCSAG behind the same taps 0.039 bit errors per codeword, so DAPNET on the held path is practical). **SignalDeck has it since 2026-10-24** (SignalDeck `12da3d84`: op 6 hold on a stub tag, re-sent after channel/VFO/tone writes, Armor taps in `assets/m17/held_<profile>.txt`, DFE kept for stock firmware); 0/90 frames decoded even with pre-shaped audio. Not a feature yet (also needs Codec2: NDK or a Java port; libm17 is GPL-2.0-only, so write from the spec). **TX through firmware is proven (2026-10-24):** symbols streamed over UART command `0x40` into a ring, RRC-shaped in the module and played through the HR-C7000 DMR modulator from TX RAM (bypassing the audio path) decoded 90/90 frames × 3 at Golay 0 with our decoder (R4t); independent decoder, TOT ceiling and the SignalDeck encoder are open; status, route list and open items in `radio_firmware/HANDOFF.md` and `radio_firmware/reviews.md`. |
| DMR group-call RX | **Settled on-air 2026-10-15** (BTECH 6X2 → this radio, simplex, CC1/TS1, `grok-deep-dive/11-…` §19): the MCU passes a group call **iff its TG is in `groups[]`** (the 32-slot RX list). ## 4. Deploy workflow (mandatory for AI agents)

After **any** successful DMRModHooks APK install, **you** must reboot the device:

```powershell
cd DMRModHooks
.\install.ps1    # build + adb install -r -t + adb reboot
```

- Do **not** tell the user to reboot — run `adb reboot` yourself.
- If no device connected, say so; do not claim deploy is complete.
- DMRModHooks **always** needs reboot; DMRTranscriptionService may not.
- Debug and release share `DMRModHooks/release.keystore` — never change debug signing without coordinating install method.
- **Launch the OEM app with `adb shell am start -n com.pri.prizeinterphone/.InterPhoneHomeActivity`, NEVER `adb shell monkey -p …`.** Monkey registers itself as the system activity controller (`isUserAMonkey()=true`); if it is interrupted/killed before exiting cleanly (reboot mid-run, adb drop, a `force-stop`/`killall` racing it) the flag sticks globally and the OEM silently refuses Channel-page Use/Edit/Delete (dialog dismisses, nothing happens) — intercom arrows still work. Recover without reflash: `printf 'q\n' | adb shell am monitor`, or reboot. Diagnose: `adb shell dumpsys activity | grep mController`.

## 5. Release policy

**Only create releases when the user explicitly asks.** Do not bump version or publish GitHub releases after routine fixes.

## 6. Coding discipline

- Change only what the task requires; no drive-by refactors.
- Match existing style in `MainHook.java` and helper classes.
- All hooks: try-catch, log via `XposedBridge.log(TAG + …)`.
- UI updates: `Handler(Looper.getMainLooper())`.
- Shared state: `volatile` static fields at top of `MainHook.java`. **Never build a `Handler`, `Looper`-bound object or anything needing a Context in a static initializer of `MainHook`**: `<clinit>` runs in the Zygote fork before the main Looper exists, and one NPE there makes LSPosed drop the whole module ("Failed to load class com.dmrmod.hooks.MainHook", 2026-10-14). Create such objects lazily from a hook.

| **12 — txContact** | `channel_txContact` stores **24-bit DMR ID** (`contact_number`), NOT contact row `_id` |
| **15 — localId** | Device DMR ID is on `DmrManager` / outgoing `DigitalMessage` (body offset 8), NOT `ChannelData`; VFO override lives in the `BaseMessage.send()` hook |
| **13 — squelch race** | 300 ms re-apply can be eaten by the in-flight `SetChannelState` ack (acks matched by cmd byte only). Since 2026-10-14 the mod also re-applies `sq=0` from an `AnalogMessageHandler.handle` after-hook whenever an analog ack arrives for a write whose `sq` was not 0 (`lastSentAnalogSq`), with the timer kept as fallback |
| **8 — squelch** | Use `AnalogMessage.send()` with `sq=0`/`sq=2`; don't rely on `syncChannelInfoWithData` for hardware |
| **10 — APRS squelch** | APRS mode overwrites `softwareSquelchThreshold` |
| **11 — relay field** | OpenGD77 exports `relay=0`; Android firmware rejects 0 → importer coerces `0→2` |
